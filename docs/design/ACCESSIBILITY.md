# Piano Sync — 접근성

기준: WCAG 2.2 AA(웹), Apple HIG(44pt hit target), Material 3(48dp touch target).

## 1. 터치 타깃

- `@media (pointer: coarse)`에서 인터랙티브 요소 최소 **44px**:
  - 버튼(`.btn`), 아이콘 버튼(`.btn-icon` 44×44), 스텝, 소스 제거, 세그먼트 행, 스위치, 입력/셀렉트, 세그먼트 컨트롤.
- Material 3의 48dp를 고려해 주요 버튼은 여유 있게 배치. 인접 타깃 간 간격 8px 이상.
- `@media (pointer: coarse)`에서 입력/셀렉트 `font-size: 16px` — iOS Safari는 포커스된 필드가 16px 미만이면 페이지를 확대하므로 이를 방지한다.

## 2. 명도 대비 (실측)

계산식: WCAG relative luminance 기준. 본문/캡션 목표 ≥ 4.5:1, 비텍스트 ≥ 3:1.

| 조합 | Dark | Light |
|---|---|---|
| `--fg` / `--bg` | 16.19 | 16.90 |
| `--fg-2` / `--bg` | 8.22 | 7.22 |
| `--fg-3` / `--bg` | 5.63 | 4.86 |
| `--fg-3` / `--surface-2` | 5.04 | 4.81 |
| `--ok` / surface | 9.24 | 5.36 |
| `--warn` / surface | 9.48 | 5.32 |
| `--bad` / surface | 6.56 | 5.10 |
| 데이터 레인 1–5 / 타임라인 배경 | 7.5–13.2 | 4.3–5.4 |
| 기준 소스 링(`--ok-ring`) / `--surface-2` | 8.83 | 4.99 |

> 라이트 테마의 데이터 색은 네온(다크) 팔레트를 그대로 쓰면 1.6–2.3:1로 비텍스트 3:1에 미달한다. 따라서 테마별 팔레트를 분리했다(`--lane-1..5`).

> 상태 틴트도 같은 문제가 있었다. 다크 rgba()를 고정으로 쓴 "기준" 소스 링은 라이트 배경에서 ≈1.7:1로 사실상 보이지 않았다. 테마별 `--ok-line/--ok-tint/--ok-ring` 등으로 분리했다. 기준 표시는 링 색뿐 아니라 `기준` 텍스트로도 전달한다.

> 초기 팔레트는 `--fg-3`(dark 4.16, light 3.56)와 라이트 `--ok`(3.59)/`--warn`(4.09)가 AA 미달이어서 위 값으로 조정했다.

## 3. 키보드 / 포커스

- `:focus-visible`에 2px 링(`--ring`).
- 입력/셀렉트 focus 시 3px 링.
- 클릭 가능한 div(구간 행, 레일 소스)에 `role="button"`, `tabindex="0"`, Enter/Space 처리.
- 타임라인은 문서 레벨 ←/→로 탐색(입력 요소 포커스 시 비활성).
- 타임라인 스크러빙은 Pointer Events로 처리해 마우스·터치·펜 모두 동작한다(`touch-action: pan-y`로 세로 스크롤은 유지).
- 설정 시트는 네이티브 `<dialog>`로 포커스 트랩/ESC 지원.

## 4. 스크린 리더

- 토스트 컨테이너 `role="status" aria-live="polite"`.
- 아이콘 전용 버튼 `aria-label`(설정, 소스 제거).
- 캔버스 `role="img"` + 설명.
- 장식 요소(배지, 진행 바) `aria-hidden` 또는 텍스트로 대체 정보 제공.
- 테마 세그먼트 `aria-pressed`.
- 폼 라벨은 `<label>`로 연결. (select/input은 라벨 내부 또는 `field-label`)

## 5. 모션 / 시각 설정

- `prefers-reduced-motion: reduce`에서 패널·토스트·시트 전환 애니메이션 제거, transition 최소화.
- 필수 진행 표시(스피너)는 유지.
- `prefers-color-scheme` 자동 테마.
- `-webkit-text-size-adjust: 100%`로 텍스트 확대 시 레이아웃 유지 노력.

## 6. 색에 의존하지 않기

- 상태는 색 + 아이콘/텍스트(예: 토스트 아이콘, `tag-ok` 텍스트).
- 구간 신뢰도는 바 + 퍼센트 툴팁/텍스트.
- 소스 구분은 색 + 알파벳 배지.

## 7. 안전 영역 / 뷰포트

- `viewport-fit=cover` + `env(safe-area-inset-*)`로 노치·홈 인디케이터 회피.
- `100dvh`로 모바일 브라우저 UI 변화 대응.
- 하단 시트는 safe-area만큼 추가 패딩.

## 8. 알려진 한계 / 미검증

- **육안 스크린샷 검수 불가 환경**: 레이아웃은 DOM 계측(오버플로우·겹침·타깃 크기·대비 계산)으로 검증했고, 픽셀 단위 시각 미학은 사람 검수가 필요하다.
- 시스템 글자 크기 확대: px 기반 타이포라 완전한 리플로우까지 보장하지 않는다(부분 대응). 향후 rem 전환 검토.
- 실제 VoiceOver/TalkBack 스크린리더 수동 테스트는 미실시.
- 색각 이상 시뮬레이션 미실시(색+텍스트 병행으로 완화).
- iOS Safari에서 `100dvh`/safe-area 동작은 실기기 확인 권장.
