# Piano Sync Switcher

같은 곡을 연주한 **2~5개의 영상**을 입력받아, 실제 **오디오 분석**으로 각 연주의 동일한 음악적
위치를 정렬한 뒤, 사용자가 정한 간격으로 화면을 바꿔가며 비교 영상을 생성합니다.

동일한 코어 엔진을 **데스크톱 앱(PySide6)** 과 **웹 앱(FastAPI + 브라우저)** 두 가지 인터페이스로
사용할 수 있습니다.

- 연주 시작 전 무음, 잔향, 서로 다른 템포, **중간의 루바토/템포 변화**, 도입부·종결부 길이 차이를
  시간 왜곡(DTW)으로 처리합니다.
- 정렬이 불안정한 구간은 신뢰도로 표시하고, 사용자가 파형 위에서 수동 대응 지점(앵커)을 보정할 수 있습니다.
- Gemini API는 **선택 기능**입니다. 키가 없어도 로컬 DTW 분석·정렬·렌더링이 모두 동작합니다.
  AI가 제안하는 위치/판단은 절대 그대로 쓰지 않고 로컬 분석으로 검증합니다.

## 설치

요구 사항: **Python 3.9 이상**, **FFmpeg** (`ffmpeg`, `ffprobe`), macOS/Linux/Windows.

```bash
# 1) FFmpeg (macOS 예시)
brew install ffmpeg

# 2) Python 가상환경 + 의존성
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 3) 실행 (데스크톱)
python run.py
# 또는
pip install -e .
piano-sync-switcher
```

FFmpeg가 PATH에 없는 경우 `.env`의 `FFMPEG_BIN`/`FFPROBE_BIN`로 경로를 지정할 수 있습니다.

## 웹 버전으로 실행 (브라우저)

```bash
python run_web.py                 # http://127.0.0.1:8765 자동 안내
# 또는
python -m pianosync.web --host 127.0.0.1 --port 8765
# 또는 설치형 사용 시
piano-sync-switcher-web
```

- 로컬 서버가 뜨면 브라우저에서 위 주소를 엽니다. 분석·렌더링은 로컬 FFmpeg로 수행되고
  브라우저는 화면(인터페이스) 역할만 합니다(업로드/다운로드 포함).
- 웹 UI는 4단계(입력·분석 → 정렬 편집 → 미리보기 → 출력)로 구성되며, 커스텀 캔버스 파형에서
  클릭 이동 / **Shift-클릭** 앵커 추가 / **우클릭** 앵커 제거를 지원합니다. 파형은 각 연주별
  레인으로, 정렬 근거(매핑 곡선·신뢰도)는 별도 레인으로 표시합니다.
- 작업 폴더는 `~/.pianosync/web`(업로드/캐시/결과). `PIANOSYNC_WEB_ROOT`로 변경할 수 있습니다.
- 진행률은 SSE(`/api/jobs/{id}/events`)로 실시간 스트리밍되며 취소를 지원합니다.

## Gemini 설정 (선택)

`.env.example`을 `.env`로 복사하고 키를 입력하거나, 앱 메뉴 **도구 → Gemini 설정**에서 입력하세요.

```bash
cp .env.example .env
# .env 에서: GEMINI_API_KEY=..., GEMINI_MODEL=gemini-2.5-flash-lite
```

- API 키는 **프로젝트 JSON에 저장되지 않습니다**. 환경 변수와 실행 중 설정만 사용합니다.
- 모델명은 설정에서 변경 가능하며 코드에 고정하지 않습니다.
- 사용 용도: 같은 곡인지 보조 판단, 저신뢰도 구간 해석, 특정 악절 위치 후보 제안.
- 제안된 위치는 로컬 정렬 결과로 스냅/검증한 뒤에만 사용합니다.

## 사용 방법

1. **탭 1 (입력 및 분석)**: 영상 A/B 선택 → 품질 설정 → **분석 시작**.
   정렬 요약(신뢰도, 저신뢰도 구간, AI 보조 판단)이 표시됩니다.
2. **탭 2 (정렬 편집)**: 상단 파형에서
   - 클릭: 해당 위치로 이동, **Shift-클릭**: 앵커(대응) 추가, **우클릭**: 앵커 제거.
   - 전환 설정(주기/모드/효과/오디오)을 정하고 **전환 지점 생성/갱신**.
   - 하단 표에서 구간(A 시작·끝, B 시작, 신뢰도, 사유)을 확인하고 경고를 살펴봅니다.
3. **탭 3 (미리보기)**: A 시간 슬라이더/전환 이동 버튼으로 위치를 바꾸고
   **프레임 새로고침**으로 같은 음악 위치의 A/B 프레임을 나란히 확인합니다.
4. **탭 4 (출력)**: 저장 경로·해상도·품질·오디오 모드를 설정하고 **최종 영상 생성**.

### 전환 모드

- **모드 1 (음악 위치 기준)**: A 타임라인의 `주기×k` 지점을 가장 가까운 음악적 이벤트(온셋)로
  스냅합니다. 전환이 항상 악구 경계에 붙고, 각 영상이 실제로 재생되는 길이는 달라질 수 있습니다.
- **모드 2 (출력 시간 기준)**: A 타임라인에서 `주기×k` 지점을 그대로 사용하므로 출력 전환 간격이
  정확히 일정합니다(스냅 없음).

전환 시점은 항상 `(A 시점 tA, B 대응 시점 tB)` 쌍으로 관리되며, B는 정렬 결과의 대응 시간에
맞춰 재생됩니다.

### 오디오 모드

- **영상 A**: A 연주 오디오를 연속 재생하면서 화면만 전환(기본, 비교 모드).
- **영상 B**: B 연주를 A 시간축에 리샘플해 정렬된 연주로 재생(템포가 다르면 스피드 변화가 있음).
- **A/B 정렬 전환**: 표시되는 영상에 맞춰 각 연주의 오디오를 전환.
- 자연스러운 음악 연결을 위해 경계에 짧은 페이드를 넣으며, 겹침형 효과에서는 오디오도 겹쳐
  영상과 길이가 같아지도록 맞춥니다. 딥(dip)·컷 효과에서는 길이를 그대로 두고 경계에서
  소리 점프(틱)가 생기지 않도록 짧게 크로스페이드합니다.

### 전환 효과

효과는 크게 세 종류입니다.

- **하드 컷** (`cut`): 겹침 없이 즉시 전환(길이 보존).
- **딥(dip) 계열**: 화면이 단색을 거쳐 전환되며 길이를 유지합니다.
  `fadeblack`(검정), `fadewhite`(흰색), `fadegrays`(회색).
- **겹침(xfade) 계열**: 두 화면을 겹쳐 전환하며 출력 길이가 효과 길이만큼 **짧아집니다**.
  `crossfade`(기본 페이드), `dissolve`, `slideleft`, `slideright`, `circleopen`.

효과 길이(초)는 크로스페이드 계열의 겹침 길이 또는 딥 페이드 길이로 사용되며, 짧은 구간에서는
자동으로 줄어듭니다(최소 구간의 40%). 오디오는 영상과 항상 같은 길이가 되도록 함께 맞춥니다.

## 프로젝트 저장

- **파일 → 저장**: 분석·정렬 결과(대응 배열), 전환 지점, 수동 앵커, 출력 설정을 JSON으로 저장.
- 다시 열면 추출·특징 분석을 반복하지 않고 캐시(`~/.pianosync/cache`)에서 이어서 작업합니다.
- 입력 파일이 이동/삭제된 경우 안내하고 다시 지정할 수 있습니다.
- API 키는 저장되지 않습니다.

## 아키텍처

```
pianosync/
├── audio/       오디오 추출(FFmpeg), 특징 추출, 캐스트, 밴드 DTW, 신뢰도
├── core/        분석 오케스트레이션, 정렬 결과/시간 매핑, 전환 지점 생성, 프로그레스
├── ai/          Gemini REST 클라이언트(선택, 응답 검증)
├── video/       오디오 조립, FFmpeg 렌더(컷/블랙페이드/크로스페이드), 프레임 추출
├── project/     JSON 저장/복원, 입력 검증
├── ui/          PySide6 데스크톱 UI(5개 영역), 파형 위젯, 백그라운드 워커
└── web/         FastAPI 서버 + 브라우저 UI(정적 HTML/CSS/JS), SSE 진행률, 작업 관리
```

- 모든 FFmpeg 호출은 안전한 인자 리스트(`shell=False`)로 실행됩니다.
- 분석·렌더링은 백그라운드 스레드에서 수행되며 취소 가능합니다.
- 긴 영상도 전체를 메모리에 담지 않도록 캐스트·밴드 DTW, 스트리밍 Ψ프로브/추출을 사용합니다.
- 데스크톱·웹은 `audio/core/video/ai/project` 코어를 공유하며, 인터페이스만 다릅니다.

## 알려진 한계

- 정렬은 국소 음악 대응이지만, 반복 구간/연주 실수가 심한 경우 DTW 신뢰도가 낮아질 수 있습니다.
  저신뢰도 구간은 붉게 표시되며 수동 앵커로 보정할 것을 안내합니다.
- `영상 B` 오디오 모드는 음악을 A 시간축에 맞추는 리샘플이라 톤이 이동합니다.
- 크로스페이드는 구간 수가 매우 많으면 필터 그래프가 커집니다(권장: 100구간 이하, 장시간 곡은 `컷` 사용).
- 미리보기는 프레임 스틸 기반입니다(실시간 A/V 재생은 현재 미지원).
- 초기 정렬 정확도 목표: 고신뢰 구간 대응 오차 중앙값 ≤ 100ms, 95분위 ≤ 250ms — 별도 기준
  타임스탬프 데이터로 측정 예정이며, 모든 연주에 보장되는 성능은 아닙니다.
